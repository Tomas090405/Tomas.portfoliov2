Déploiement et brassage de switchs

Mission 1 · Réseau

Plusieurs salles de classe avaient des switchs anciens, non administrables, et un câblage difficile à suivre. L'objectif était de les remplacer par des modèles administrables, de refaire le brassage proprement et de séparer les flux grâce aux VLAN.

Switchs PoEVLANSSHBrassage
Voir les détailsMasquer les détails

Environnement technologique

  • Switchs administrables 48 ports avec PoE (pour les bornes Wi-Fi)
  • Baie de brassage, panneaux de brassage, câbles RJ45 catégorie 6
  • Accès en console (câble série) puis en SSH pour la configuration
  • Testeur de câble réseau et étiqueteuse

Démarche et étapes

  1. Relevé de l'existant : j'ai noté pour chaque salle les prises murales, les postes branchés et l'état du câblage.
  2. Plan d'adressage : avec mon tuteur, on a défini un VLAN par type d'usage.
  3. Préparation des switchs : nom, mot de passe administrateur, adresse IP de gestion, création des VLAN, désactivation des ports non utilisés.
  4. Installation en baie et brassage : pose du switch, câbles courts et rangés, étiquetage de chaque câble et de chaque port.
  5. Tests : vérification de chaque prise avec le testeur, puis connexion d'un poste dans chaque VLAN pour vérifier l'adresse IP reçue et l'accès aux serveurs.
  6. Documentation : mise à jour du tableau de correspondance prise / port / VLAN.
VLANNomUsage

30ELEVESPostes des salles de cours
40WIFI-INVITESAccès Internet des visiteurs

Problèmes rencontrés et solutions

Une boucle réseau a ralenti toute une salle.Un câble avait été branché entre deux prises de la même salle. J'ai vérifié que le protocole Spanning Tree était activé sur les switchs pour bloquer automatiquement ce type de boucle, puis j'ai retiré le câble.
Certaines prises murales n'étaient pas repérées.J'ai testé les prises une par une et j'ai refait l'étiquetage des deux côtés, prise et panneau de brassage.

Gestion de l'Active Directory

Mission 2 · Systèmes

À chaque rentrée, l'école accueille de nouveaux étudiants et professeurs qui ont besoin d'un compte. L'objectif était de créer ces comptes rapidement, sans erreur, et de les ranger clairement pour leur appliquer les bonnes règles.

Windows ServerAD DSGPOPowerShell
Voir les détailsMasquer les détails

Environnement technologique

  • Windows Server avec le rôle Active Directory (AD DS)
  • Console « Utilisateurs et ordinateurs Active Directory »
  • Console de gestion des stratégies de groupe (GPO)
  • Fichier CSV des inscriptions fourni par l'administration
  • PowerShell pour la création des comptes en grand nombre

Démarche et étapes

  1. Organisation de l'annuaire : une unité d'organisation (OU) pour les élèves, une pour les professeurs, avec des sous-OU par formation et par année.
  2. Convention de nommage : identifiant sous la forme prenom.nom.
  3. Création des groupes : un groupe par classe, qui sert ensuite à donner les droits sur les dossiers partagés.
  4. Import des comptes : un script PowerShell simple lit chaque ligne du fichier CSV et crée le compte dans la bonne OU. Le mot de passe doit être changé à la première connexion.
  5. Stratégies de groupe : des GPO différentes pour les élèves (restrictions sur les postes) et pour les professeurs.
  6. Vérification : connexion avec un compte test de chaque type sur un poste de salle.

Problèmes rencontrés et solutions

Deux étudiants avaient le même prénom et le même nom.Le script s'arrêtait car l'identifiant existait déjà. J'ai ajouté une vérification : si l'identifiant existe, un chiffre est ajouté à la fin (prenom.nom2).
Les accents du fichier CSV s'affichaient mal.Le fichier était dans le mauvais encodage. Je l'ai réenregistré en UTF-8 et j'ai retiré les accents des identifiants.

Wi-Fi sécurisé de l'école

Mission 3 · Réseau et sécurité

L'ancien Wi-Fi utilisait une seule clé partagée, connue de presque tout le monde. L'objectif était que chacun se connecte avec son propre compte, avec un réseau séparé pour les visiteurs.

WPA2-Entreprise802.1XRADIUS / NPSSSID
Voir les détailsMasquer les détails

Environnement technologique

  • Bornes Wi-Fi alimentées en PoE par les switchs de la mission 1
  • Contrôleur Wi-Fi pour gérer toutes les bornes au même endroit
  • Serveur RADIUS (rôle NPS sur Windows Server) relié à l'Active Directory
  • WPA2-Entreprise (802.1X) pour les comptes de l'école

Démarche et étapes

  1. Choix de l'architecture : un réseau « École » avec connexion par compte AD, et un réseau « Invités » isolé, avec accès Internet seulement.
  2. Configuration du RADIUS : installation de NPS, ajout du contrôleur Wi-Fi comme client RADIUS, règle qui autorise uniquement les groupes Élèves et Professeurs.
  3. Configuration des bornes : création des deux SSID, chacun associé à son VLAN.
  4. Isolation des invités : le VLAN invités n'a pas de route vers le réseau interne, et les appareils invités ne se voient pas entre eux.
  5. Tests : connexion depuis un PC portable, un Android et un iPhone, avec un compte élève, un compte professeur et un compte désactivé.
  6. Guide utilisateur : une fiche simple qui explique comment se connecter.

Problèmes rencontrés et solutions

Les téléphones Android refusaient de se connecter.Les versions récentes d'Android demandent de valider le certificat du serveur. J'ai indiqué dans le guide l'option à choisir et le nom de domaine à saisir.
Un compte désactivé pouvait encore se connecter pendant quelques minutes.Cela venait de la réplication entre contrôleurs de domaine. Avec mon tuteur, on a jugé le délai acceptable et je l'ai noté dans la documentation.

Gestion de parc avec GLPI

Mission 4 · Gestion de parc et support

L'inventaire était tenu dans un tableur rarement à jour, et les demandes d'assistance arrivaient par mail ou à l'oral. L'objectif était d'installer GLPI pour avoir un inventaire automatique et un outil de tickets.

GLPI 10DebianApache · PHP · MariaDBLDAP
Voir les détailsMasquer les détails

Environnement technologique

  • Serveur Linux Debian (machine virtuelle)
  • Apache, PHP et MariaDB (base de données de GLPI)
  • GLPI version 10 et GLPI Agent sur les postes Windows
  • Liaison LDAP avec l'Active Directory

Démarche et étapes

  1. Préparation du serveur : installation de Debian, Apache, PHP et MariaDB. Création d'une base et d'un utilisateur dédiés à GLPI.
  2. Installation de GLPI : par l'interface web, puis changement des mots de passe des comptes par défaut.
  3. Liaison avec l'Active Directory : les utilisateurs se connectent à GLPI avec leur compte habituel.
  4. Inventaire automatique : GLPI Agent déployé sur les postes, qui remontent seuls leurs informations.
  5. Tickets : catégories (réseau, compte, matériel, imprimante, logiciel) et règles qui attribuent le ticket au bon technicien.
  6. Présentation au personnel : comment déclarer une demande.

Problèmes rencontrés et solutions

Certains postes n'apparaissaient pas dans l'inventaire.Le pare-feu bloquait la communication entre l'agent et le serveur. J'ai ajouté une règle pour autoriser ce flux, puis forcé un inventaire.
L'import LDAP récupérait aussi des comptes désactivés.J'ai modifié le filtre LDAP dans GLPI pour ne récupérer que les comptes actifs.
